# 語彙の層 — 読んで意味が思い浮かぶ語を選ぶ

このファイルのルールはすべて**復元テスト**で判定する: この語だけを読んで、読者は「誰が・何を・どうする」を具体的に思い浮かべられるか。

## 目次

1. 英語直訳の名詞句は、「誰が・何を・どうする」の文に書き直す
2. 比喩・意味の広い語は、指している操作を説明してから使う
3. 専門用語をそのまま使ってよい基準・言い換える基準
4. ぼかし動詞を具体的な動作・条件に置き換える
5. 「など」は削除するか範囲を示す
6. 「これ」「それ」は「この API」のように名詞を添える
7. 中身のない形容詞を数値・動作・条件に置き換える
8. 要注意ワード一覧
9. キーとなる名詞を省かない・分解する
10. 対になる概念は、対義語のペアで書く
11. 用語の一貫性と初出の書き方

## 1. 英語直訳の名詞句は、「誰が・何を・どうする」の文に書き直す

英語の術語を直訳して名詞のまま使うと（false rejection →「誤った拒否」）、原語を知らない読者には何のことか分からない。名詞のかたまりをやめて、主語と動詞のある文に書き直す。

- ❌ 「これは誤った拒否として現れる」（読者:「誤った拒否って何？」）
- ✅ 「本来は許可すべきリクエストを、システムが誤って拒否してしまう」

英語圏の概念を紹介するときは、直訳語を作らず、原語（false rejection）を出してから中身を日本語の文で説明する。

## 2. 比喩・意味の広い語は、指している操作を説明してから使う

「凍結」「閉じ込める」「回復する」のような意味の広い語は、書き手の頭の中では具体的な操作を指していても、読者には伝わらない。

- ❌ 「設定ファイルを凍結する」（読者:「冷やすの？」）
- ✅ 「設定ファイルを zip に固めて変更不可にする（以降これを凍結と呼ぶ）」

初出でどんな操作を指すのかを書き、以後はその語で通す。定義した語を途中で別の語に言い換えない。あとで一度も参照しない造語・名前は、そもそも導入しない。

## 3. 専門用語をそのまま使ってよい基準・言い換える基準

読者層にとっての教科書用語はそのまま使ってよい（例: 機械学習の読者に「過学習」「学習率」の説明は不要）。次の3種類は日本語に言い換えるか、説明を足す。

- **原典の造語**（論文・製品ドキュメントだけで通じる用語）→ 初出で中身と目的を説明する。名前を並べるだけで済ませない
- **業界内の隠語** → 日常の言葉に言い換える。例: 「オラクル」→「正解を教えてくれる仕組み」、「held-out」→「訓練に使っていない検証用データ」、「キュレーションする」→「人手で選別する」
- **数学・論文調の抽象語**（「系」「上記」「当該」）→ 使わない。指している相手を名指しする（「上記の設定」→「手順2で作った設定」）

## 4. ぼかし動詞を具体的な動作・条件に置き換える

「対応する」「実施する」「適切に」「見合わせる」「検討する」は、受け手によって解釈が割れる。何をするのかを動詞でズバリと書く。

- ❌ 「エラー時は適切に対応してください」
- ✅ 「エラー時はジョブを停止し、#alert チャンネルに通知してください」

## 5. 「など」は削除するか範囲を示す

「など」は範囲を曖昧にする。削除して列挙し切るか、直後に範囲を表す語を置く。

- ❌ 「ドライバーなど」 → ✅ 「ドライバーなどの工具」または「ドライバーとレンチ」

## 6. 「これ」「それ」は「この API」のように名詞を添える

「これ」「それ」だけだと、読者は指している対象を探しに戻ることになる。

- ❌ 「Location API の活用が重要です。これには、さまざまなメリットがあります」
- ✅ 「Location API の活用が重要です。この API には、さまざまなメリットがあります」

## 7. 中身のない形容詞を数値・動作・条件に置き換える

「劇的に」「飛躍的に」「包括的な」「本質的な」は、評価だけあって根拠がない。読者は程度を確かめられない。

- ❌ 「パフォーマンスが劇的に改善しました」
- ✅ 「p99 レイテンシが 100ms から 10ms になりました」

数値は比較対象とセットで出す。「人手には届かない」と言葉で丸めずに「44.5% vs 43.6%」のように両方の数値を書く（差の大きさで文の意味が変わる）。平均値は内訳が追える形で書く。スコア・評価値を使う話では、そのスコアがどこから来るか（正解データか、LLM の判定か、自作テストか）を必ず書く。

## 9. キーとなる名詞を省かない・分解する

- ❌ 「そのファイルを取り込んで」 → ✅ 「config.yaml を取り込んで」
- ❌ 「コストを削減する」 → ✅ 「変動費を削減する」（大きな名詞を分解して、指したいものにピッタリの語を選ぶ）
- ❌ 「何名かの動物」 → ✅ 「3匹の動物（犬、猿、キジ）」

## 10. 対になる概念は、対義語のペアで書く

対比・場合分けを書くときは、2つの概念が対義語のペアになっているかを確認する。対になっていない語を混ぜると、読者は2つの関係を頭の中で組み立て直すことになる。

- ❌ 「本来は許可すべきリクエストを、システムが誤ってブロックしてしまう」（許可⇔ブロックは対になっていない）
- ✅ 「本来は許可すべきリクエストを、システムが誤って拒否してしまう」（許可⇔拒否の対義語ペア）

使い方は3つある。

1. **対比する動作・状態は対義語で書く**（許可⇔拒否、成功⇔失敗、有効⇔無効、追加⇔削除）。片方だけカタカナ語や比喩にしない
2. **「AでなければB」と書けるのは、AとBが対義語のときだけ**。対になっていないなら納得感が出ない。「Aでない場合は〜する」と条件を明示する形に変える
3. **場合分けに漏れがないと示したいときは、「AとB」ではなく「AとA以外」と書く**。片方を他方の否定で表すと、漏れがないことがそのまま伝わる。ただし「A以外」の中身が大事な場面では、具体的に列挙する

## 11. 用語の一貫性と初出の書き方

- 同じものを指す語を混ぜない（「ユーザー」と「利用者」の混在など）
- 英語の専門用語は初出で「English（日本語訳）」の語順で併記する。略記は「Coding Agent（以降、Agent と呼ぶ）」のように宣言してから使う
- 製品名・技術名は正式表記で書く（JavaScript を Java と書かない。大文字小文字も正確に）
