# レビュー結果の HTML レポート

レビューモードの指摘は、GitHub Diff 風の HTML レポートで提示する。テンプレート（assets/review-template.html）と生成スクリプトはスキル内にあるので、**指摘データの JSON を書いてスクリプトを1回実行するだけでよい。テンプレート HTML を読まないこと**（コンテキストの無駄になる）。

## 手順

1. 4パスのレビューで集めた指摘を、下記スキーマの JSON にまとめて書き出す。出力先はスクラッチパッド（無ければ `mktemp -d`）。対象文書のあるリポジトリ内には書かない
2. スクリプトで HTML を生成する:

   ```bash
   python3 ~/.claude/skills/clear-japanese/scripts/build_review.py <dir>/review-data.json <dir>/review-<文書名>.html
   ```

3. `open <dir>/review-<文書名>.html` でブラウザ表示する
4. チャットには全文を繰り返さず、件数サマリー（例: 「指摘8件: 高2・中4・低2。HTML を開きました」）と総評1〜2文だけを書く

## JSON スキーマ

```json
{
  "doc": "articles/drafts/foo/draft.md",
  "date": "2026-07-25",
  "summary": "総評1〜2文（任意）。最も直す価値がある問題は何か",
  "findings": [
    {
      "id": 1,
      "severity": "高",
      "layer": "語彙",
      "title": "指摘の一言タイトル",
      "location": "第2段落",
      "line": 12,
      "before": "原文（プレーンテキスト）",
      "after": "修正案（プレーンテキスト）",
      "reason": "なぜ読者に伝わらないか。どのテストに失敗したか"
    }
  ]
}
```

- `severity` は `高` / `中` / `低`、`layer` は `語彙` / `文` / `構造` / `AIっぽさ`（スクリプトが検証する）
- `location`（文中の位置の説明）と `line`（行番号）は任意
- `before` / `after` はプレーンテキストで書く。**diff のマークアップは不要**（テンプレートが文字単位の差分を自動計算して赤/緑表示する）
- 段落の移動・削除など「置換で表現できない指摘」は、`before` に対象箇所、`after` に移動・削除後の姿を書き、`reason` で操作を説明する

## 反映指示の処理（クリップボード式ループ)

ユーザーは HTML 上で指摘ごとに採用/却下を選び、修正案テキストを直接編集できる。「結果をコピー」ボタンで次の形式がクリップボードに入り、チャットに貼られる:

```
## clear-japanese レビュー反映指示
対象: articles/drafts/foo/draft.md

- 指摘1（指摘の一言タイトル）: 採用（編集あり）
  修正後: ユーザーが編集した最終テキスト
- 指摘2（…）: 却下
- 指摘3（…）: 未判断
```

これが貼られたら次のように処理する:

- **採用**: 対象文書の該当箇所を「修正後:」のテキストで置き換える。「編集あり」の場合、ユーザーが手を入れた最終版なので**一字も変えずにそのまま**使う
- **却下**: 何もしない。代替案の再提案もしない
- **未判断**: 適用せず、残っていることをユーザーに一言伝える

## Markdown 形式へのフォールバック

次の場合は SKILL.md の Markdown 形式（指摘ブロックの列挙）で提示する:

- ブラウザを開けない環境（SSH 先、`open` が失敗する等）
- ユーザーがテキストでの指摘を求めたとき
- 指摘が2件以下で、チャットで足りるとき
