# レビューの委譲と並列実行

執筆したエージェントに自分の文章をレビューさせない。書いたばかりの文章には書き手のバイアスがかかり、執筆時の思い込みをそのまま引き継ぐ。レビュワーには成果物とレビュー基準だけを渡し、執筆の経緯（構想メモ、それまでの会話）は渡さない。

## 目次

1. 実行形態の選び方
2. 並列レビューの手順
3. 修正の適用

## 1. 実行形態の選び方

文章の規模と重要度でレビューの重さを変える。並列レビューはトークンを大きく消費するので、すべての文章に適用せず、価値が見合うときだけ使う。

1. **短い文章（目安2,000字まで）や途中稿** → 同一セッションで4パスを順に実行する（SKILL.md のレビューモード）。委譲は不要
2. **長い文章や公開前の最終レビュー** → 観点別のサブエージェントに委譲し、並列で実行する（このファイルの手順2）
3. **サブエージェント機能が使えない環境** → 直列で4パスを実行する。ただしパスごとに、成果物とそのパスの references ファイルだけを読み直す。他の作業の続きの流れでレビューしない

## 2. 並列レビューの手順

### 2-1. 観点別レビュワーを同時に起動する

観点ごとのレビュワー4体（構造・語彙・文・AIっぽさ）を、1回の呼び出しでまとめて起動する。各観点は独立していて読み取りしかしないので、並列にできる。レビュワーに修正はさせず、指摘の収集だけをさせる。

各レビュワーへの指示には、次の4要素を必ず入れる。曖昧な指示は、観点の重複と抜けを生む。

1. **目的**: どの層の問題だけを検出するか
2. **出力形式**: 指摘ごとに「原文引用 / 修正案 / 理由 / 重大度 / 確信度」
3. **参照ファイル**: 対象文書のパスと、その観点の references ファイルのパス
4. **境界**: 他の層に踏み込まない。文書の主張・内容の正誤に意見しない

指示のテンプレート（語彙の層の例）:

```
次の文書をレビューし、指摘の一覧だけを最終メッセージで返してください。文書の編集はしないでください。

- 目的: 語彙の層の問題だけを検出する。~/.claude/skills/clear-japanese/references/vocabulary.md を読み、そのルールと復元テストで診断する
- 対象: <文書のパス>
- 出力形式: 指摘ごとに「原文引用 / 修正案 / 理由（どのルール・テストに失敗したか）/ 重大度（高・中・低）/ 確信度（0〜100。100=確実に問題、50=どちらとも言えない）」
- 境界: 文の組み立て・構造・AIっぽさには触れない。内容の正誤にも意見しない。文書の意味を変える指摘は、確信度を下げて出す
```

### 2-2. 指摘を検証してから統合する

レビュワーは、指摘を頼まれれば健全な文章にも指摘を出す。集まった指摘を鵜呑みにせず、次の順で絞り込む。

1. **確信度でふるいにかける**: 確信度80未満の指摘は捨てる
2. **ルールの実在を確認する**: 「〜のルールに違反」という指摘は、references に本当にその記述があるかを確認する。無ければ捨てる
3. **重複をまとめる**: 同じ箇所への指摘は1つに統合する。層をまたぐ場合は重大度の高い方に寄せる
4. **重大度順に並べる**: 高 → 中 → 低

### 2-3. 1本のサマリにして提示する

統合した指摘を1本にまとめ、SKILL.md の「指摘の出力形式」に従って提示する（既定は HTML レポート。references/html-report.md の JSON にまとめて生成する）。総評（最も直す価値がある問題は何か）を summary に入れる。修正の採否は書き手（人間）が決める。レビューは判断材料の提供であって、決定ではない。

## 3. 修正の適用

並列のレビュワーに修正までさせない（同じファイルへの書き込みが衝突するうえ、層をまたぐ修正の整合が取れない）。修正を頼まれたら、統合後の指摘リストに沿って、1つのエージェントが構造 → 語彙 → 文 → AIっぽさの順に直列で適用する。

## 出典

Anthropic の公式ガイドに基づく。

- Claude Code ベストプラクティス（https://code.claude.com/docs/en/best-practices）: 書いた本人に採点させない。レビュワーには成果物と基準だけを見せる
- マルチエージェントリサーチシステム（https://www.anthropic.com/engineering/multi-agent-research-system）: 委譲指示の4要素。並列化は独立・読み取り中心のタスクに限る。トークン消費はチャットの10倍以上
- Code Review の設計（https://claude.com/blog/code-review）: 並列レビュー → 確信度による検証 → 集約・重複排除・重大度順ランキングの3段パイプライン
