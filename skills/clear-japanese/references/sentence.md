# 文の層 — 英語の文の組み立てを日本語に戻す

LLM の日本語の多くは、英語の文の組み立てをそのまま日本語に写した書き方（機械翻訳の時代から「欧文直訳体」と呼ばれてきたもの）になっている。文単位の診断はここを見る。

## 目次

1. 人でないものを主語にしない
2. 1文に主張を2つ以上詰め込まない（ただし機械的に刻まない）
3. 隠れた主語を洗い出し、主語ごとに文を分ける
4. 主語と述語のねじれを直す
5. 冗長表現の置き換え
6. 二重否定を避け、肯定文で書く
7. 助詞の連続・修飾語の位置
8. 体言止めは本文で避ける
9. 事実と意見を区別する

## 1. 人でないものを主語にしない

英語の enable / allow / prevent / improve の直訳で、機能・エラー・概念が主語になった文が生まれる。人（ユーザー・読者・開発者）を主語にするか、結果を中心に書き直す。

- ❌ 「この機能はユーザーにデータ出力を可能にします」
- ✅ 「この機能を使用すると、データを出力できます」
- ❌ 「エラーがアプリケーションの起動を妨げました」
- ✅ 「エラーにより、アプリケーションを起動できませんでした」

書き換えの型は4つある。

1. 主語を外す
2. 結果・状態を中心に書き直す
3. 人を主語にする
4. 「〜すると」「〜により」の形に変える

## 2. 1文に主張を2つ以上詰め込まない（ただし機械的に刻まない）

長い文そのものは問題ではない。関連する事実の補足や連続する動作は「〜で」「〜し」でつないでよい（「Symfony は PHP の Web アプリケーションフレームワークで、MVC モデルを採用しています」は1文のままで読みやすい）。分割するのは次のときだけ。

1. 主張・理由・条件が2つ以上絡み、最も伝えたいことが文末に埋もれているとき
2. 逆接でない「〜が」で話題が切り替わっているとき（「昨日試したのですが、うまくいきました」）
3. 節が連なって、主語と述語の対応を追い直す必要があるとき

分割するときは、文を区切ってから順番を入れ替えてよい。短文に刻みすぎない。ぶつ切りの均等なリズムは、それ自体が読みにくい（ai-smell.md の「文の長さのリズム」を参照）。

## 3. 隠れた主語を洗い出し、主語ごとに文を分ける

1文の中に複数の登場人物の動作が混ざると、誰の動作か分からなくなる。

- ❌ 「クイックリプライボタンをタップすると、返信用のボタンが表示される仕組みを提供しています」（表示するのはボット、タップするのはユーザー、提供するのは書き手。3者が混在）
- ✅ 「レストラン検索ボットがボタンを表示します。ユーザーはボタンをタップして要望を伝えます」

## 4. 主語と述語のねじれを直す

主語だけ読んで述語につながるかを確認する。

- ❌ 「新しいシステムの特徴は、〜業務を効率化できます」（「特徴は」→「できます」がつながらない）
- ✅ 「新しいシステムは〜業務を効率化できます」または「新しいシステムの特徴は、〜業務を効率化できることです」

## 5. 冗長表現の置き換え

| ❌ | ✅ |
|---|---|
| 確認することができます | 確認できます |
| 開発を行う | 開発する |
| 圧縮できるかどうか検証します | 圧縮できるか検証します |
| 〜という方法もあります | 〜も使用できます |
| どのように実現するか紹介します | 実現方法を紹介します |
| 改善した結果になります | 改善した結果です |

## 6. 二重否定を避け、肯定文で書く

- ❌ 「マージしたブランチは、残したままにしないでください」
- ✅ 「マージしたブランチは、削除してください」
- 例外: 「電源を切らないでください」のような禁止事項は否定形のまま

「〜しないとは限らない」「〜でないわけではない」は必ず肯定形に直す。

## 7. 助詞の連続・修飾語の位置

同じ助詞を1文の中で繰り返さない。

- ❌ 「今日はAさんは定例会議は欠席します」 → ✅ 「Aさんは今日の定例会議を欠席します」

修飾語は置く位置で意味が変わる。語順を入れ替えても意図が保たれるかを確認する。

- 「いろいろな漢字の読み方」（複数の漢字それぞれの読み方）⇔「漢字のいろいろな読み方」（ある1つの漢字の複数の読み方）

## 8. 体言止めは本文で避ける

体言止め（名詞で文を終える書き方）は「何がどうなるのか」の情報が落ちる。説明の本文では避け、箇条書きの項目・見出し・手順に限定する。ただし完全にゼロにもしない（ai-smell.md の「文の長さのリズム」を参照。全部の文が同じ形で終わると単調になる）。

## 9. 事実と意見を区別する

事実には根拠を示し（「テスト結果によると」「ログを見ると」）、意見・推測にはそれと分かる目印を付ける（「筆者の見解では」「原因は〜と推測している」）。読者が「これは確かめられた事実か、書き手の推測か」を文ごとに判別できる状態にする。
