# 構成 — 見出しと段落の役割を揃える

## 「具体かつ概要」を目指す

具体性と詳しさは別の軸である。「具体的に」と言われて経緯をすべて書いたり、「短く」と言われて対象を抽象語に置き換えたりしない。

| | 概要 | 詳細 |
| --- | --- | --- |
| 抽象 | 桃から生まれたやつが、何名かの動物と一緒に、悪いやつを倒す話 | ある人が川で拾ったものから生まれたやつが、食べ物を渡して何名かの動物を連れていき、悪いやつのいる島で戦う話 |
| 具体 | 桃から生まれた桃太郎が犬、猿、キジを仲間にし、鬼を退治する話 | おばあさんが川で拾った桃から桃太郎が生まれ、成長した桃太郎が犬、猿、キジにきびだんごを渡して仲間にし、鬼ヶ島で鬼を退治する話 |

物語の概要を求められた場合は、左下が目標となる。登場人物と行動は明確なまま、物語を理解するのに必要な出来事へ絞っている。手順書や詳細設計で必要な細部まで省くという意味ではない。

技術文書でも、「運用を改善する」だけでは対象も変化も分からない。原文に情報があるなら「経理担当者による請求データの転記を自動化する」のように要点を具体化する。概要では画面上のクリック順や内部関数の説明を積み増さない。独立した仕様・約束・実施条件は本文に残し、説明の経緯や操作過程を一段上の動作にまとめる。詳細を別の節へ移す場合も、文書から消さない。ただし、制約・例外・判断に必要な根拠を、短くするために落とさない。

概要に整理するときは、まず読み手が判断するために必要な主体・対象・動作と、その条件を選ぶ。その後で重複や操作の細部を整理する。通常の清書との違いや省略の判断例は [意味を保つ判断手順](preservation.md) に従う。

## 読者が知りたい順に並べる

文章の目的と想定読者を、依頼と原文から把握する。報告なら結果と理由、手順なら実行順、概念の説明なら概要と具体例の順を基本とする。書き手の作業順をそのまま本文の順序にしない。

読み手が最初の数文で話題と要点をつかめるようにする。結論を早めに示す場合も、何についての結論か分からないほど前提を省かない。文書全体の結論を、背景や課題など役割の異なる節の冒頭に繰り返し置かない。

## 見出しが予告する内容を書く

「背景」「解決したい課題」「提案」などの見出しは、読者に文書内の位置を知らせる。具体的な主張の文へ一律に置き換えない。既存テンプレートがある場合は、その区分を尊重する。

節の役割は、見出しの単語からではなく、読者に答える問いから決める。

| 役割 | 答える問い | 置く内容 |
| --- | --- | --- |
| 背景 | 現在どうなっているか | 現在の仕組み、運用、観察された事実 |
| 課題・目的 | 何に困り、何を達成したいか | 困りごと、影響、望む状態 |
| 提案・方針 | どう実現するか | 採用する変更、担当、実施方法 |
| 理由・根拠 | なぜそう判断したか | 原文にある根拠、選定理由 |
| 条件・制約 | どこまで当てはまるか | 適用範囲、例外、限界 |

すべての文書にこの章立てを当てはめない。元のテンプレートと文書の目的に合う役割を選ぶ。一つの主張を説明する理由や具体例は、その主張と同じ節に置ける。複数の独立した問いを同じ節で扱わない。

特に「何を達成したいか」と「どの手段を使うか」は分ける。提案文の冒頭に目的が書かれていても、文全体が手段を説明していれば課題の節には置かない。現状と課題が短く自然につながる場合は一つの節でもよいが、そこへ具体的な変更内容まで入れない。

### 役割を分ける例

原文:
> 課題：新入社員が研修日程を把握できていない。日程を一か所で確認できるようにしたい。そのため、研修日程をまとめたページを作る。

清書:
> 課題：新入社員が研修日程を把握できていない。日程を一か所で確認できるようにしたい。
>
> 提案：日程を一か所で確認できるよう、研修日程をまとめたページを作る。

「そのため」というつながりがあっても、ページを作る話は手段なので提案へ移す。本文をそのままにして見出しを「課題と対応」に変えるだけでは、課題と手段を分けたことにならない。

### 配置を直した後の読み直し

見出しと、その下の段落を組にして読む。冒頭だけでなく最後の段落まで、同じ問いへの説明になっているか確認する。別の役割の文を見つけたら、修飾語や条件と一緒に適切な節へ移す。足りない理由や目的を創作してつじつまを合わせない。

本文で「組織の問題がある」と書くだけでは内容が分からない。例えば、原文にある「承認が3部門に分かれ、確認の往復に時間がかかる」という状況を示す。「課題は3つある」と数を予告することは問題ないが、項目名だけで説明を終えない。原文にある具体的な状況を使って説明する。見出しの役割名と、本文の中身を欠いた説明は区別する。

## 段落を一つの問いに絞る

段落の冒頭で扱う対象や要点を示し、その理由・具体例・条件を続ける。直前の説明を読んで生まれる「何のことか」「なぜ必要か」「どうするか」という疑問に、次の文や段落が答えているかを確かめる。答えが原文にあれば配置を整え、なければ推測で補わない。文と文の接続は [cohesion.md](cohesion.md) に従う。別の問いに答える文は、適切な段落へ移す。

重要な条件や説明を「余談」に追いやらず、必要な主張の近くに置く。一方、同じ内容を言い換えただけの段落や、内容のない前置きは削る。

## 文章・リスト・表を使い分ける

- 理由や因果の説明は、関係を読み取れる文章にする。
- 独立した要件は箇条書き、実行順のある操作は番号付きリストにする。
- 複数の対象を共通の観点で比較する場合は表を使う。

項目数だけで形式を決めず、読み手が何を追うかで選ぶ。並べる項目の種類と粒度を揃え、理由・操作・感想を同列にしない。意味の異なる項目を、数を減らすためにまとめない。
