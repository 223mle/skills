# 語彙 — 対象と動作が分かる言葉を選ぶ

## 名前だけで理解できるかを判断する

用語の一般性は想定読者に照らして判断する。読者が知っている専門用語はそのまま使う。説明が必要な場合は、初出で何を指すかを短く示す。名称の直訳だけで分からないなら、対象・動作・用途を原文と提供された文脈の範囲で説明する。

- 主体や対象を広い分類名だけで表している場合は、読み手が特定できる名前や役割を添える。
- 識別子や数値には、何の値で、この説明にどう関係するかを示す。値を置くだけで説明したことにしない。
- 抽象的な動作や比喩には、何にどんな変化を加えるのかを示す。
- 操作の必要性が伝わらない場合は、原文にある目的を近くに置く。

すべての用語に定義や目的を付ける必要はない。読者が意味を取り違えたり、前の説明を探し直したりする箇所を直す。必要な情報がない場合は、名前や理由を創作しない。

## 書き換え例

以下は文脈から対象や意味が分かっている場合の例であり、特定の語を禁止する一覧ではない。

| 原文 | 清書例 |
| --- | --- |
| スクリプトが処理する | 請求書の生成スクリプトが、受注データからPDFを作成する |
| 調査基準は `abc1234` | この説明は、対象リポジトリのコミット `abc1234` のソースコードを確認して記載した |
| 誤った拒否が発生する | 本来は許可すべきリクエストを、システムが誤って拒否する |
| 設定を凍結する | 設定ファイルへの書き込みを禁止する |

## 指すものを見失わせない

「これ」「それ」の対象が複数考えられる場合は、「この設定」のように名詞を添える。対象が明らかな場合は、自然な省略を残す。

同じ対象は同じ名前で呼ぶ。語彙を変えるためだけに同義語を混ぜない。専門用語と説明の順序は、読者に伝わりやすいほうを選ぶ。原語の併記は検索や後続の説明に必要な場合に限る。

## 抽象語を具体化しすぎない

「適切に」「大幅に」「など」は、範囲や判断を曖昧にしている場合に直す。原文に具体的な条件や数値があれば使い、なければ作らない。概要を読ませたい箇所に実装の詳細を積み増さない。

対比する概念は、同じ観点・粒度の言葉で表す。ただし、語の対称性を整えるために条件や意味の違いを消さない。
